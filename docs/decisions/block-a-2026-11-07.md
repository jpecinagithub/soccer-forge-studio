# Informe del Bloque A — Acceso técnico a Muse Spark 1.3 (interino)

> **Corrección 2026-11-07 (usuario): el agente del proyecto es Muse de Meta, no el modelo `muse-spark-1.3` alojado en OpenCode.** Este informe documenta la vía de OpenCode (API + CLI), que se probó por una confusión de nombres: el modelo de OpenCode y el agente Muse comparten familia (Muse Spark 1.3) pero son productos distintos. El resultado A1 NO-GO aplica solo a esa vía de OpenCode, no al agente del proyecto. El Bloque A se replantea como: qué puede hacer el agente Muse con el vídeo y con qué herramientas. Lo útil que queda de este informe: el fragmento 35-65 s, el prompt, el esquema y el validador siguen siendo válidos, y la prueba de imagen demuestra que el agente (vía CLI con Mimo) describe fotogramas correctamente.

Fecha: 2026-11-07. Entorno: Oracle (`appforge-oracle`, 143.47.63.169), OpenCode CLI **1.19.1**, credencial `OPENCODE_API_KEY` en `/opt/spark-chat/.env` (secreto del servidor, modo 600; la clave nunca se mostró ni se copió fuera del servidor). Estado: **A1 NO-GO — no hay ruta utilizable a Muse Spark 1.3 sin una decisión del usuario**. El resto de criterios queda pendiente del desbloqueo, salvo A2 (entrada de vídeo), que ya tiene un resultado negativo firme.

## A1. Autenticación — NO-GO

La credencial existe y es válida: las peticiones llegan al proveedor y devuelven errores del proveedor, no de autenticación. Lo que falla es el modelo:

| Modelo probado | Resultado | Detalle |
|---|---|---|
| `opencode/muse-spark-1.3-contributor-free` | `ProviderModelNotFoundError` | El ID ya no existe en opencode 1.19.1. Sugerencias del proveedor: `muse-spark-1.2`, `muse-spark-1.3`, `beam-free`. Era el ID que funcionaba el 2026-10-16. |
| `opencode-go/muse-spark-1.3-contributor` | HTTP 400, no reintentable | «This Go model trains on request data. Turn on "Allow paid endpoints that train on request data"» en la consola de OpenCode (ajuste de privacidad del espacio de trabajo). Requiere consentimiento del usuario: los datos de la petición podrían usarse para entrenar. |
| `opencode/muse-spark-1.3` (pago) | HTTP 402, no reintentable | «Insufficient account funds» (igual que el 2026-10-16). |

**Decisión pendiente del usuario (una de las dos):**

1. Activar el ajuste de privacidad en la consola de OpenCode para usar el modelo contributor gratuito (con la implicación de entrenamiento con los datos enviados), o
2. Añadir fondos a la cuenta de OpenCode para usar el modelo de pago.

**El chatbot desplegado no está afectado:** su `.env` fija `SPARK_MODEL=opencode/mimo-v2.6-flash-free`, no el ID de Muse Spark que ha dejado de existir.

## A2. Entrada de vídeo — NO-GO por CLI; imágenes SÍ funcionan

Fragmento preparado: `B1-frag-35-65.mp4`, 30,00 s exactos, 1920×1080 H.264 + AAC, 32.087.131 bytes, SHA256 `4612eda507b6f37f6907113da5ec04920344212cd50af647b6b6521b7b6dff81`, desplazamiento 35,00 s. Versión MOV equivalente (`B1-frag-35-65.mov`, 30,00 s). Ambos están en Oracle (`/tmp/soccer-block-a/`) y en `data/clips/work/frag/` (fuera de Git).

- `opencode run -f <mp4>` **no puede llevar vídeo**: el adjunto pasa por la herramienta de lectura del agente, que responde `Cannot read binary file`. Probar con `--dir` no lo arregla.
- Peculiaridad del CLI 1.19.1: con `-f` presente, un mensaje posicional se interpreta como ruta de fichero (`Error: File not found: <mensaje>`). El mensaje debe pasarse por **stdin**.
- **Prueba de imagen (control positivo):** un fotograma JPG del fragmento (t=10,5 s rel. = golpeo del penalti), enviado con `-f` y el mensaje por stdin al modelo Mimo, fue descrito correctamente: «Un jugador amarillo (nº 21) ejecuta una jugada a balón parado frente al área contra la defensa roja de Georgia, con el portero posicionado bajo palos durante el 0-0 al minuto 10:32 España–Georgia». Leyó la imagen y hasta el reloj. Duración ~10 s, coste 0, tokens entrada 2832 / salida 64.

**Consecuencia arquitectónica:** por CLI solo es viable el brazo «Muse + herramientas» (fotogramas como imágenes). El brazo «Muse directo» (vídeo crudo) necesita otro transporte, aún por investigar una vez desbloqueado el modelo: API del servidor de OpenCode (`opencode serve`) o API Responses de Zen con entrada de vídeo (la vía directa ya demostró el 2026-10-16 el bloqueo 403 del tier gratuito fuera del cliente oficial).

## A4. Coste y duplicados — sin observar

No hubo ninguna llamada correcta a Muse Spark 1.3, así que no hay consumo observado. Queda pendiente distinguir: (a) la facturación del proveedor (qué cobra OpenCode por llamada) y (b) nuestra prevención de trabajos duplicados (reutilización de sesión `-s`, idempotencia). No se asume que el proveedor evite cargos duplicados.

## A5. Salida estructurada — preparado, sin respuesta que validar

- Prompt del fragmento: `docs/evaluation/fragment-prompt.txt` (acciones observadas, tiempos relativos al fragmento, incertidumbres por dimensión, repeticiones sin generar jugadas, jugadores desconocidos sin inventar).
- Esquema de respuesta: `docs/evaluation/fragment-response-schema.json`.
- Validador: `scripts/validate-fragment-response.py` — comprueba esquema, cobertura [0, 30] sin huecos, tiempos dentro del fragmento, que ninguna jugada empiece en una repetición, penalti (10,50 s rel.) y tiro de play-C (20,80 s rel., resultado null), repetición inicial clasificada como replay, e incertidumbres coherentes. Probado contra un ejemplo de referencia: **11/11 comprobaciones pasan**.
- Una respuesta HTTP correcta no basta: la validación es la de arriba. Sin modelo desbloqueado no hay respuesta real que validar.

## A6. Rendimiento — sin medir
