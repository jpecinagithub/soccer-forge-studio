# Cierre del proyecto — Soccer Forge Studio (2026-11-08)

## Decisión

El proyecto se cierra en su estado experimental actual, por decisión del
usuario (2026-11-08). Se conservan código, informes y resultados. No se
encadenan más pruebas con la expectativa de que el siguiente ajuste vaya a
producir el análisis completo que se buscaba.

## Cambio de premisa: presupuesto cero

- **Premisa anterior (2026-11-06):** el coste no era una limitación; se
  medía e informaba, nunca era criterio de corte.
- **Premisa actual (2026-11-08):** presupuesto **cero** para GPU y
  servicios de pago. **Sustituye a la anterior.**
- **Consecuencia:** la ejecución inicial única del fine-tuning (exp3) no
  tiene una vía viable demostrada con los medios actuales: requiere GPU
  temporal de pago, y trasladar el entrenamiento estimado para GPU a la
  CPU y dejarlo funcionar no se recomienda sin una previsión fundada.

## Valoración del usuario (2026-11-08)

- El servidor actual permite experimentar y procesar vídeo lentamente. No
  disponer de GPU no demuestra por sí solo que el proyecto sea imposible.
- Todavía no hay un motor fiable para analizar cada jugada. Los problemas
  pendientes son de calidad: confusiones del balón, seguimiento incorrecto
  y eventos sin suficiente evidencia. Alquilar una GPU tampoco garantizaría
  resolverlos.
- El fine-tuning propuesto no tiene una ejecución viable demostrada con
  nuestros medios actuales.

## Conclusión documentada

> «No se ha demostrado una solución que cumpla la calidad exigida con los
> recursos disponibles y sin gasto adicional.»

Esto justifica el cierre sin afirmar que el análisis automático de fútbol
sea imposible.

## Estado final por experimento

- **Fase 0 (2026-11-06, `80f55ac`):** especificación, diccionario de
  eventos, contrato de datos v0.1.0, set de evaluación, criterios de
  aceptación. Cerrada.
- **Anotación B1 v2 (`a7c5e11`):** 8 jugadas, 11 eventos, 5 puntuables;
  material exploratorio, adjudicación humana pendiente.
- **Bloque A / OpenCode (`ce8cb5e`):** ruta descartada; Muse Spark 1.3 por
  API no es un requisito; el motor de análisis quedó pendiente de
  selección.
- **Exp2 Qwen (`988ee26`, correcciones `0faadab`):** 0/5 eventos de
  referencia recuperados a 1 fps; configuración no validada. Referencia
  experimental documentada; anclaje temporal atribuido al modelo.
- **Exp1 YOLO + ByteTrack (`11cd7fb`, correcciones `11f1b29`):** balón en
  vista de campo solo en el 4,5 % de la salida del seguimiento; sin señal
  para reconstruir ni un pase.
- **Exp1B (`8a2518e`, correcciones `fb34505`):** pierden detector y
  seguidor; el 4,5 % se descompone (crudo @0,25 13,8 % → seguidor conserva
  32,8 % → 4,5 %).
- **Exp1C (`83cf381`):** el enlazador propio (Kalman + puerta) iguala el
  techo del detector (0,395 ajuste / 0,333 comprobación) pero encadena
  falsos positivos en congestión (tasa de error 0,41 en comprobación).
- **Exp2 detector especializado (`83396f9`, correcciones `8f44e84`):**
  candidato 1 (`bambezius/yolo11n-soccernet-ball`) recupera mucho más
  balón (B1 0,748 frente a 0,455; B3 independiente 0,550 frente a 0,100)
  pero no demuestra menos confusiones; sin licencia declarada, solo
  referencia experimental. FootAndBall descartado (Avg Rec 0,022).
- **Exp3 preparación del fine-tuning (`a1c616a` + `e87a373`):** receta
  única Ytr1200, condiciones verificadas ("procedencia limpia" pendiente;
  los pesos heredarían no comercial + AGPL-3.0), evaluación corregida,
  GPU temporal presentada (~$5,34 RunPod Secure RTX 4090). **No
  ejecutada.**
- **B2 (España 2-0 Georgia):** sigue reservado, sin tocar ni descargar.

## Qué queda conservado

- Repo público https://github.com/jpecinagithub/soccer-forge-studio
  (`main` en `e87a373` al cierre), con `SPEC.md`, `docs/decisions/`
  (informes de todos los experimentos), `scripts/` y referencias
  versionadas.
- Datos locales (gitignored): clips B1 y B3 verificados por SHA256,
  referencias v3, predicciones y evaluaciones.
- Servidor Oracle: el plan de despliegue quedó documentado, no ejecutado;
  no hay despliegue del producto.

## Qué queda abierto (sin afirmar imposibilidad)

- Un detector propio afinado (receta exp3) sigue siendo la vía documentada
  si cambian los recursos.
- La deduplicación previa al enlazador queda como propuesta sin
  implementar.
- B2 reservado para una comparación final, si el trabajo se reabre.
- El trabajo sirvió: se identificaron y midieron los obstáculos antes de
  construir un dashboard que aparentase una capacidad que el sistema
  todavía no tiene.
